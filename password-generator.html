How the estimate works

Random-password entropy is estimated from the available character pool and generated length. Passphrase entropy is estimated from independently selected compound words plus optional random additions. These figures are approximate, not guarantees.

Privacy design

  • Uses crypto.getRandomValues().
  • No network request is made.
  • No password is placed in the page URL, cookies or local storage.
  • Reports mask passwords unless you explicitly choose otherwise.

Practical tips

  • Use a unique password for every account.
  • Prefer at least 15 characters when supported.
  • Store credentials in a reputable password manager.
  • Enable multifactor authentication for important accounts.

Common mistakes

  • Reusing one strong password everywhere.
  • Adding predictable dates or names.
  • Sending passwords through ordinary chat or email.
  • Saving unencrypted password lists or screenshots.
What password length should I use?

Use at least 15 characters when the service permits it. The default of 20 characters provides a strong practical starting point.

Are symbols required?

Not always. Symbols can increase the character pool and satisfy website rules, but length and unpredictable generation matter more than a fixed mixture.

Is a passphrase secure?

Yes, when it uses several independently selected random words. Avoid quotations, lyrics, personal sentences and common expressions.

Does this page store generated passwords?

No. The generator keeps only the current in-memory batch and clears it when the page is closed or reloaded.

Can I reuse a generated password?

No. Generate a different password for every account so one breach does not expose other services.

Is this suitable in Malaysia?

Yes. Password-security principles are universal. The interface defaults to English and does not require currency or measurement settings.
